## 1. Executive Summary

This audit rigorously inspects the code, datasets, checkpoints, benchmark scripts, and manuscript sources (`AuthorKit27/AnonymousSubmission2027.tex`) of the **Aether Routing Network (ARN)** following Phase 1 review at AAAI-27. 

The audit reveals a stark divergence between the sound architectural premise (a frozen 4.38M BERT-tiny trunk paired with Factored Attention Routing and linear-chain CRF tagging) and the empirical evidence submitted. Multiple headline metrics, hardware figures, baseline comparisons, and ablation claims in the submitted manuscript cannot be reproduced from or traced to existing code and result files. In several instances, numbers in tables were mathematically impossible for the stated sample sizes, baselines were evaluated without training, or experimental components (such as LoRA adaptation and tool-prefixed BIO schemas) were emulated or described without underlying implementations.

This audit establishes a complete ledger of every reported metric, scans all files for secrets and absolute paths, maps dependencies, audits CRF/loss/routing mechanics, and outlines the precise questions requiring user clarification before beginning Phase 2 repo cleanup and Phase 3 experimental rebuild.

## 6. Model & Training Architecture Verification

Detailed inspection of the core PyTorch modules in `ARN/` reveals:

### 1. CRF Invalid BIO Transition Masking
- **Status:** **NOT IMPLEMENTED.**
- In `ARN/crf.py:L12`, `self.transitions = nn.Parameter(torch.randn((num_tags, num_tags)))`.
- In `ARN/crf.py:L54-80` (`viterbi_decode`), candidate step scores are computed via:
  ```python
  next_tag_var = viterbi_vars.unsqueeze(2) + self.transitions.unsqueeze(0)
  ```
- There is **no masking** with $- \infty$ for invalid transitions (e.g., `O` $\rightarrow$ `I-slot`, `B-X` $\rightarrow$ `I-Y`). The transitions are completely unconstrained learnable parameters. The paper's claim that invalid transitions are forbidden by design is currently false in code.

### 2. Start and End Transition Parameters
- **Status:** **IMPLEMENTED.**
- `ARN/crf.py:L13-14` instantiates:
  ```python
  self.start_transitions = nn.Parameter(torch.randn(num_tags))
  self.end_transitions = nn.Parameter(torch.randn(num_tags))
  ```
- These are properly integrated into the forward algorithm (`L20, L29`), sentence scoring (`L35, L46`), and Viterbi decoding (`L56, L65`).
- *Note:* In Equation 7 of the paper, start and end transitions were omitted from the equation, creating a math mismatch with the code.

### 3. Loss Normalization & BCE vs CRF Weighting
- **Status:** **IMPLEMENTATION MISMATCH WITH EQUATION 10.**
- In `ARN/model.py:L39-43`:
  ```python
  active_tokens = attention_mask.sum() + 1e-8
  raw_slot_loss = self.crf.loss(emissions, tags, attention_mask)
  slot_loss = raw_slot_loss / active_tokens
  total_loss = tool_loss + self.config.LAMBDA_SLOT * slot_loss
  ```
- Look closely at what `crf.loss()` returns in `ARN/crf.py:L52`:
  ```python
  return torch.mean(forward_score - gold_score)
  ```
  `crf.loss()` already computes the **mean** sentence NLL across the batch: $\frac{1}{B} \sum_{b=1}^B \text{NLL}_b$.
- Dividing `raw_slot_loss` by `active_tokens` (where `active_tokens = attention_mask.sum()` across the **entire batch**) divides the batch mean by the total active tokens in the batch ($B \times \bar{N}$).
- Meanwhile, `tool_loss = nn.BCEWithLogitsLoss()(tool_logits, tool_labels)` averages over $B \times K$.
- Consequently, `slot_loss` is scaled down by approximately $B \times \bar{N}$ twice, which is completely different from the per-token length normalization defined in Equation 10 of the paper ($\frac{1}{N_{\text{active}}} \text{NLL}$ per sequence).

### 4. Tool Registry Dynamism
- **Status:** **STRICTLY CLOSED-WORLD / FIXED $K$.**
- In `ARN/far.py:L10`:
  ```python
  self.tool_embeddings = nn.Embedding(num_embeddings=num_tools, embedding_dim=hidden_dim)
  ```
- The tool count $K$ is hardcoded at initialization. Adding tools requires instantiating a new embedding matrix and re-adapting (as demonstrated in `expand_checkpoint.py`). Any claim of "dynamic tool registry" support at runtime is unsupported.

## 8. Root Causes of Reviewer Rejection

The AAAI-27 Phase 1 review was fundamentally sound. The reviewers rejected the paper not on its architectural premise, but on the integrity of the empirical evidence:
1. **Data Leakage in Random Split:** Randomly partitioning 13,798 augmented instances (where each template generated multiple paraphrases) allowed verbatim templates to exist in both training and test sets, inflating subset accuracy to 90.2%.
2. **Manufactured Numbers in Table 3:** Percentages with $N=50$ that were mathematically impossible ($65.0\%, 55.0\%, 15.0\%$).
3. **Ghost References & Citations:** Citing "92.3% in Table 1" with no matching table cell; citing Qin et al. 2019 as GL-GIN (it is Stack-Propagation).
4. **Untrained Baselines:** Comparing ARN against an untrained random JointBERT baseline in ablation tables.
5. **Simulated Innovations:** Presenting "Tool-Prefixed BIO Tagging" as an implemented neural solution when only an emulation script over 4 samples existed.
6. **Vague / Fabricated Hardware Numbers:** Citing 5.55 MB RAM with no protocol, 14.2 ms on ARM with no hardware benchmark script, and identical 16.96 MB disk size for models with different parameter counts.
7. **Cross-Paper Multipliers Presented as Comparisons:** Claiming "810x vs Gorilla" without benchmarking Gorilla or establishing comparable tasks.
